01 · how a finding is made

Reads the jar. Never runs it.

jarsnitch reads the bytecode of every method, follows the calls from the plugin's entry points, and matches what it finds against its rules.

  1. inplugin.jarone jar, several, or a plugins/ folder
  2. readRead the bytecodeCA FE BA BE class files, plugin.yml, nested jars
  3. traceCall graph from entry pointsmain class, event handlers, commands
  4. matchRulescalls, strings and files, then combinations
  5. outReportwhat it means, legitimate uses, where it is, whether anything calls it

03 · command line

Same engine in your terminal.

A single binary, no Java needed. Exit code 2 can fail a CI job or an update script.

CLI reference →

cargo install jarsnitch
curl --proto '=https' --tlsv1.2 -LsSf https://github.com/mattbaconz/jarsnitch/releases/latest/download/jarsnitch-installer.sh | sh
powershell -ExecutionPolicy Bypass -c "irm https://github.com/mattbaconz/jarsnitch/releases/latest/download/jarsnitch-installer.ps1 | iex"
scanjarsnitch scan plugins/
diffjarsnitch diff MyPlugin-1.4.jar MyPlugin-1.5.jar
jsonjarsnitch scan plugins/ --json
Exit codes

0No High findingsThe update adds no High findings

This shows what the code can do, not proof of what it will do. A clean report isn't a guarantee.
